## Cadence verdict

Do **not** run literal 400 words every day forever.

| Format | Cadence | Role |
|---|---|---|
| Short playbook | 3–4 / week (~400–700 words) | Owns exact searches ("Gmail → QuickBooks receipts") |
| Deep pillar / hub | 1 every 1–2 weeks (1,200–2,000 words) | Clusters playbooks; what AI answer engines cite |
| Daily 400 sprint | Optional 2–3 week launch only | Seed the library, then stop |

**Sustainable output:** ~20 pieces/month without burnout.

### Why not daily 400 forever?

- **Daily 400:** Good for a 2–3 week launch sprint. Weak long-term — thin pages, duplicate mush, agents ignore shallow near-duplicates. Use as batch mode: write 4 playbooks Sunday, schedule Mon–Thu.
- **Weekly deep only:** Strong for authority, too slow for coverage. One URL/week never owns the long-tail tool-pair searches people actually type. Pillars need child playbooks underneath.

## How the site should present it

Think **library**, not blog dump. Navigation by **pain** and by **software** — not by date.

### Site structure

| Section | URL pattern | Purpose |
|---|---|---|
| Home | `/` | Brand + one line. Links into hubs, not a wall of posts. |
| Hubs (pillars) | `/topics/receipt-capture` | Deep dive + lists child playbooks |
| Playbooks | `/playbooks/gmail-to-quickbooks-receipts` | Stable URLs, tool names in slug |
| Tools index | `/tools/quickbooks` | Every playbook that mentions that app |
| About | `/about` | Who Operate-IQ is. No pricing, no audit CTA yet. |

### Playbook page template

1. Symptom headline (search language)
2. Who this is for (firm type + stack)
3. What is leaking time / margin
4. Before → after workflow map (text + simple diagram)
5. Steps to implement (numbered, copyable)
6. Human-in-the-loop guardrail
7. Failure modes / when not to automate
8. Related playbooks + parent hub

**Presentation rule:** Date archives are secondary. Primary browse paths are Topics and Tools. A visitor (or agent) should land on a playbook and immediately see the parent hub + sibling fixes.
